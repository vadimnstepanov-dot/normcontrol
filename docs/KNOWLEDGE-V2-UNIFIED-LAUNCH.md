# Единый запуск проверки пакета

Запуск новой проверки выполняется на одном экране: документы, необязательное название, направления, опубликованные нормативные наборы одной проектной области и, при необходимости, проверенный опыт рецензий. Пользователь нажимает одну кнопку «Запустить проверку» и сразу переходит к ходу обработки. Отдельных страниц подготовки, состава и повторного подтверждения нет. Название по умолчанию берётся из первого файла. Единственный доступный нормативный набор предлагается отмеченным; пользователь видит и может изменить выбор.

При включённом knowledge-v2 СТО выбираются вместе с грамотностью, логикой и оформлением. Если выбраны СТО, запуск без нормативов запрещён. При отключении направления СТО форма явно сообщает, что соответствие СТО не оценивается. Доступ и готовность выпусков проверяются повторно внутри транзакции. Если обработчик недоступен, пакет остаётся в очереди — отсутствие подключения не требует повторного подтверждения.

Ошибки выводятся в той же форме; при работе JavaScript выбранные файлы и настройки сохраняются. При отключённом JavaScript после ошибки файлы потребуется выбрать заново (ограничение браузера). До записи пакета проверяются все загруженные файлы. Ошибка сохранения или нормативного запуска откатывает пакет и удаляет записанные для него файлы. `LaunchReceipt` закрепляет ключ отправки и отпечаток документов/настроек: повтор той же отправки открывает уже созданную проверку, а изменённый повтор отклоняется. Это работает и без СТО.

Запуск атомарно ставит выбранные обычные направления в очередь локального обработчика и создаёт нормативную проверку с неизменным снимком выпусков. Старый каталог СТО в этот запуск не подставляется. Нормативный обработчик ждёт завершения обычных этапов; ожидание не расходует попытки. Два исполнителя не запускают пакетные проверки на общей модели одновременно. Готовый нормативный этап имеет приоритет перед следующим обычным пакетом.

Пока нормативный этап ожидает, главная страница показывает фактический ход обычных этапов и отдельное уведомление о СТО. Страница пакета содержит переходы к обоим этапам и их отчётам. Пакет не объявляется завершённым раньше окончания нормативного этапа. Ошибка предшествующего этапа не считается успешным нормоконтролем.

К уже выполняющемуся пакету можно добавить СТО: обычные направления, идентификатор локального задания, контрольные точки и результаты не изменяются. Повторное нажатие с тем же ключом не создаёт второй нормативный запуск. Для повторной проверки и дополненного комплекта создаётся новая версия пакета; перед её запуском пользователь подтверждает актуальные нормативы. Предыдущий выбор предлагается повторно, прошлые отчёты сохраняются.

Неутверждённые экспертом требования дают предварительные выводы; кандидаты не входят в рабочий нормативный выпуск. Единый запуск не отменяет ограничения полноты нормативной базы и не означает подтверждённое соответствие всего документа.
