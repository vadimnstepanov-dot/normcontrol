# Перенос нормативной области в JSON

Формат `normcontrol.normative-area`, версия `1` переносит настроенный состав одной области. Кнопки **«Выгрузить область · JSON»** и **«Загрузить область · JSON»** находятся внизу её страницы. Выгрузка доступна читателю области; загрузка — пользователю с правами редактирования и загрузки нормативов.

## Что входит

| Поле | Содержание |
| --- | --- |
| `format`, `version`, `exported_at` | Идентификатор формата, версия и дата выгрузки |
| `area` | Название, описание, режим автоматической публикации |
| `sources` | Идентификаторы оригиналов, имена файлов, SHA-256; `metadata` с названиями и реквизитами утверждения |
| `profiles` | Профили документов, наследование, условия применимости и привязки к источникам |
| `requirements` | Действующие требования и кандидаты с условиями, исключениями, обязанностями и точными цитатами |
| `glossary.entries` | Термины, определения, обозначения, сокращения; включая неактивные варианты |
| `glossary.choices` | Выбранный активный вариант каждого термина/обозначения/сокращения |
| `interdocument_requirements` | Междокументные правила области и их нормативные основания |

Не входят оригинальные файлы, пользователи, пароли, права доступа, адреса и ключи LLM, результаты проверок, рецензии и история изменений. Это перенос текущей конфигурации, а не резервная копия всей системы. Уже удалённые требования и архивные профили остаются в истории исходной системы.

Формальная схема: [normative-area.schema.json](schemas/normative-area.schema.json). Дополнительно сервер проверяет ссылки, отсутствие циклов наследования и соответствие цитат оригиналам. Схема описывает переносимый контейнер; содержимое карточек проходит проверку действующей версии подсистемы требований.

## Как перенести область

1. Выгрузите JSON исходной области и отдельно сохраните её оригинальные нормативные документы.
2. Создайте новую целевую область. Для подготовки к импорту выключите автоматическую публикацию в её настройках.
3. Загрузите оригиналы и дождитесь окончания чтения (`source.ingest`). Предварительное извлечение требований моделью не обязательно. Байты файлов должны совпадать: пересохранённый документ имеет другую контрольную сумму. Состав оригиналов должен точно соответствовать JSON.
4. Выберите **«Загрузить область · JSON»**. Система проверит формат, наличие оригиналов и основания записей, затем покажет количество профилей, требований, терминов и связей.
5. Подтвердите импорт один раз. Сверка цитат и восстановление состава выполняются обработчиком на вычислительном хосте без дополнительных генераций LLM.
6. Проверьте восстановленные кандидаты и при необходимости подтвердите их. Новая публикация строится по обычным правилам качества.

Идентификаторы области и импортированных профилей/карточек создаются заново. Ссылки внутри импортированного состава переназначаются согласованно. Выбор активного определения глоссария сохраняется. Экспертные отметки качества сбрасываются: загруженный JSON не является доказательством того, что другой эксперт действительно подтвердил запись. Исходная уверенность модели сохраняется отдельно.

Реквизиты источников переносятся как данные с отметкой «Перенесены из JSON; требуется сверка». Их можно исправить в разделе «Источники». Они не заменяют проверенные цитаты и не меняют контрольные суммы оригиналов. Поля `metadata`: `short_title`, `full_title`, `approved_by`, `signed_by`, `approval_date`, `approval_document_number`, `approval_document_date`; значения — строки в исходном написании, даты не смешиваются с датой вступления норматива в силу.

Импорт заменяет автоматически сформированные профили и карточки целевой области, сохраняя их историю. При наличии экспертных правок, дополнительного оригинала, незавершённой обработки или изменении области после предварительной проверки импорт отклоняется. Используйте новую область; существующие экспертные решения не перезаписываются. Закреплённые нормативные выпуски и запущенные проверки не изменяются.

## Ограничения версии 1

- UTF-8 JSON, до 32 МиБ; до 100 оригиналов, 100 профилей и 10000 карточек требований/глоссария суммарно.
- Оригиналы загружаются отдельно и предварительно читаются. Независимо подготовленный JSON может импортироваться без анализа LLM: для DOCX обработчик проверяет цитаты по структуре самого оригинала, для PDF/DOC — по уже извлечённым фрагментам этого источника. Совпадения одной контрольной суммы недостаточно: проверяются физический файл, цитаты, координаты и контекст, включая вложенные условия.
- Хеши контекста пересоздаются по проверенному местному оригиналу; текст цитат и их смещения не подменяются. Различия структуры извлечения могут потребовать повторного чтения оригинала. Система не подставляет похожие пункты вместо отсутствующих.
- Успешная сверка подтверждает происхождение цитат, а не полноту или правильность интерпретации нормы. Импорт не присваивает экспертную отметку и не публикует нормативный выпуск автоматически. Глоссарий относится к области и не требует профиля технического документа.
- После импорта эксперт может явно подготовить и опубликовать выпуск без повторного извлечения LLM. Обработчик закрепляет успешную команду импорта, проверяет контрольную сумму её состава и создаёт обычные поисковые индексы. Выпуск получает режим `imported_reference` и отметку «полнота не подтверждена». Публикация сохраняет блокирующие вопросы карточек: они не исполняются моделью и не дают окончательных нарушений. Экспертное подтверждение остаётся отдельным действием; изменения карточек после подготовки требуют нового выпуска.
- Смена выбора термина не означает экспертного подтверждения его нормативной полноты.
- При неподдерживаемой версии контейнера, неизвестной ссылке, цикле, подмене цитаты или повторе ключа JSON загрузка отклоняется. Частичная замена состава не применяется.

## API

`GET /normcontol/api/v2/areas/{id}/export.json` — выгрузка.

`POST /normcontol/api/v2/areas/{id}/import/` — проверка/подтверждение. Требуются сессия, CSRF и `Idempotency-Key`.

```json
{
  "document": {"format": "normcontrol.normative-area", "version": 1},
  "apply": false
}
```

В примере `document` сокращён: передавайте полный файл. Ответ предварительной проверки содержит `stats` и `revision`. Подтверждение передаёт тот же `document`, `apply: true` и `expected_revision` из ответа. При отсутствии оригиналов возвращаются `missing_sources` с именами и SHA-256. Ответ `202` содержит `command_id`; завершение проверяется через штатный API команд. Повтор подтверждения с тем же ключом возвращает исходную команду.

Необязательный массив `controls` переносит состояния объектов: `kind` (`area`, `source`, `profile`, `card`, `link`), `id` (для области — `area`), `enabled`, `deleted`. Это настройки применимости, а не экспертное подтверждение. Версии управления создаются в целевой системе.
