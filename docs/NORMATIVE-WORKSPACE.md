# Рабочее пространство нормативной базы

Нормативная база организована деревом: **область → профиль документа → требование → первоисточник**. Междокументные требования и глоссарий принадлежат области.

После загрузки нормативов система извлекает структуру и цитаты, предлагает профили и требования, проверяет происхождение, подготавливает нормативный выпуск и публикует допустимый состав. Кандидаты и вопросы полноты показываются отдельно; публикация не превращает неподтверждённую запись в экспертно проверенную норму. Последний пригодный выпуск сохраняется при ошибке обработки нового.

В карточке требования слева показан первоисточник, справа — формулировка, условия, исключения, применимость, статус и история. Эксперт может редактировать, добавлять, разделять, объединять или отклонять записи с сохранением нормативных оснований. Унаследованное требование открывается у владельца либо уточняется явно для дочернего профиля. Рецензии пользователей доступны в соответствующих карточках профилей и требований.

## Глоссарий

Из нормативных документов извлекаются три типа записей: термины и определения, обозначения, сокращения. Реестр показывает тип, источник, дату загрузки и активность. Разные значения одного названия сохраняются отдельно. Первым активным становится определение из раньше загруженного оригинала, независимо от порядка окончания анализа. При конфликте остальные значения подсвечиваются как неактивные.

Эксперт может выбрать другое значение с обоснованием: прежнее станет неактивным. Выбор сохраняется при очередном анализе. Редактирование и удаление не стирают историю. В нормативный поиск выпуска поступают только выбранные активные определения, прошедшие необходимые проверки качества.

## Навигация и перенос

В разделе «Источники» система показывает краткое название с титульного листа и дату утверждения. Для каждого оригинала извлекаются полное название, утвердившее/подписавшее лицо, номер и дата утверждающего документа. Извлечение выполняется одним ограниченным, кешируемым обращением к LLM по начальной части документа; каждое значение сверяется с точной цитатой. Отсутствующие и неоднозначные реквизиты остаются неустановленными. Для ранее загруженных источников доступна кнопка «Извлечь реквизиты», без повторного выделения всех требований.

Эксперт редактирует реквизиты кнопкой «Редактировать». Изменения требуют обоснования, сохраняются с автором и датой и не затираются при повторном анализе. Название файла и SHA-256 не редактируются. Пока название не извлечено, поле «Источник» показывает имя файла. Реквизиты можно перенести вместе с областью в JSON; отметки происхождения отделены от экспертного подтверждения требований.

Системную левую панель можно свернуть кнопкой в верхней строке. Состояние запоминается отдельно для пользователя. Дерево нормативов сворачивается независимо; профили раскрываются по мере обращения, без загрузки всей базы в браузер.

Полный состав области переносится в [документированном JSON-формате](NORMATIVE-AREA-JSON.md); оригиналы загружаются отдельно.

## Журнал проверки

При запуске проверки доступна опция сохранения подробного журнала. Она закрепляется вместе с параметрами запуска и не требует дополнительных генераций LLM. Журнал выгружается в XLSX: паспорт, параметры, документы, нормативный состав, применимость, план, поиск RAG, запросы/ответы модели, решения, доказательства, длительности, ошибки и целостность доставки.

Журнал может содержать исходный текст документов. Его видят только пользователи, которым доступны соответствующая проверка и нормативные источники. Секреты подключения не включаются; изображения представлены контрольными суммами. Для выключенного логирования полный журнал задним числом не восстанавливается. Пропуски доставки отражаются явно.

Очистка старых журналов выполняется командой `manage.py purge_check_logs` (по умолчанию 30 дней); журналы работающих и приостановленных проверок сохраняются. Администратор может включить её в ежедневное обслуживание.

## Единые действия с объектами

В реестрах и карточках областей, профилей, требований, глоссария, источников и междокументных правил используются карандаш (редактировать), корзина (удалить) и питание (активировать/деактивировать). Подсказки доступны мышью и экранному диктору. Изменение состояния требует обоснования и проверки версии, фиксируется в журнале. Удаление исключает объект из действующего состава, сохраняя доказательства и историю. Отключение родителя исключает дочерние профили из следующей публикации. Уже закреплённые проверки не изменяются. До публикации обновлённого состава область не предлагается для новых запусков.

Для глоссария активация неактивного значения выбирает его вместо ранее действующего. Удалённые объекты отображаются с отметкой и заблокированными действиями; восстановление не выполняется обычным переключателем. Обработка и публикация области блокируют изменение её состава.
