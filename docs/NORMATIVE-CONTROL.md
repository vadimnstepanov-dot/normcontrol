# Доказательный нормативный контроль

## Обновление каталога

После обновления кода завершите текущие проверки и пересоберите каталог из локальных нормативных источников:

```text
python sto_rag/normcontrol_v5.py catalog
python sto_rag/normcontrol_v5.py catalog-audit
```

В Windows используйте Python из виртуального окружения; в Linux — соответствующий `python3` или `.venv/bin/python`.

Новая версия активируется только после проверки происхождения цитат и при отсутствии активной проверки. Если проверка происхождения не пройдена, прежний каталог остаётся действующим. После обновления кода перезапустите локальную службу и worker в свободном состоянии. Для старых заданий создайте повторную проверку: их результаты относятся к прежней реализации и версии каталога.

## Что содержит карточка

- Неизменённую цитату, контрольную сумму источника и адрес.
- Отдельные обязанности, включая явно перечисленные элементы; у каждого свой идентификатор.
- Родительские условия и исключения.
- Текст зависимых таблиц и пунктов, включая ссылки на другой доступный СТО.
- Отдельно неразрешённые ссылки и образцы ссылок внутри составляемого документа.
- Тип документа, упоминания стадии, условия применимости и необходимость фактов о проекте/комплекте.

Отсутствующий источник, превышение бюджета зависимости или неоднозначная ссылка сохраняются как ограничение. Они не считаются автоматически проверенными. Упоминание стадии в стандарте является условием для проверки по документу, а не достаточным основанием исключить требование.

## Области доказательства

LLM может заявить, что проверяет конкретный раздел или документ. Программа независимо сопоставляет фактически переданные блоки с извлечённым оригиналом, включая дочерние разделы, и записывает отпечаток области. После сокращения контекста доказательство пересчитывается.

Произвольная поисковая выборка не доказывает отсутствие во всём документе. Непереданные абзацы, непроверенные изображения и неразрешённые отсылки препятствуют автоматическому подтверждению отсутствия. Для программной проверки заголовков таблиц используется полный набор заголовков; неоднозначный столбец «№» не считается отсутствующим только по названию.

## Решения по обязанностям

Ответ `coverage` для `checked` или `not_applicable` должен содержать `checks` для каждой обязанности: её идентификатор, результат и точные цитаты проверяемого документа. Цитирование самого стандарта вместо проверяемого документа не подходит.

- `checked` означает выполненную проверку, а не отсутствие нарушений.
- `outcome=satisfied` означает, что представлены доказательства выполнения обязанности.
- `outcome=violated` требует отдельного замечания и независимой перепроверки.
- `not_applicable` требует явного факта о проекте, объекте или стадии; отсутствие поискового совпадения не подходит.
- `insufficient`/`unknown` означают непроверенную область.

Общие отсылки к типовым механизмам не заменяют требуемое конкретное описание. Старые положительные решения без нового набора доказательств при формировании отчёта показываются как неподтверждённые; первоначальные ответы модели сохраняются.

## Раздельные показатели качества

Штатный `catalog-audit` возвращает четыре независимых измерения:

1. `provenance`: точность цитат, адресов зависимостей и атомарных смещений.
2. `obligation_completeness`: наличие обязанностей и кандидаты на смысловую ревизию выделения.
3. `applicability`: наличие разметки и необходимость подтверждения условия фактами проекта.
4. `dependencies`: разрешённость нормативных ссылок.

Положительный результат по происхождению не означает полной смысловой валидации СТО. Количество учтённых фрагментов не является метрикой полноты выделения требований.

Отчёт отдельно показывает нормативный охват по парам документ–требование, непроверенные области, неприменимые требования и число подтверждённых замечаний с нормативным основанием. Оформление, структура и содержание сохраняются отдельными предметами проверки.

## Контрольные тесты

```text
python -m unittest nc5.tests.test_normative_contract
```

Для запуска из корня задайте `PYTHONPATH=sto_rag`. Тесты синтетические: полные/неполные области, вложенные разделы, выдуманные цитаты, положительные и отрицательные условия применимости, составные обязанности, зависимости, атомарные цитаты и переносы в названиях колонок. Частные значения эталонных документов в рабочие промпты не добавляются.

Русские словоформы нормализуются через pymorphy3 с кэшем; при отсутствии зависимости сохраняется лексический поиск. Оценка поиска должна включать отдельный размеченный набор, а не только количество найденных замечаний.
