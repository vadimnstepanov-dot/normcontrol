# Vision-проектор: отдельный этап проверки

Сейчас `--mmproj` загружается вместе с моделью на всё время работы `llama-server`. Для текущего пакета менять профиль нельзя: его задания по изображениям уже включены в этап технической логики. Остановка с новой версией алгоритма нарушила бы проверку совместимости сохранённого задания.

Контрольный одинаковый запрос на этом компьютере после чистого запуска дал около **82 ток/с генерации и 1497 ток/с prefill без проектора**, **60 ток/с и 940 ток/с с проектором**. Измерение показывает смысл отдельного этапа, но не гарантирует тот же выигрыш на любом документе. Длительно работавший процесс с проектором деградировал значительно сильнее; это отдельная причина для осторожного перезапуска после сохранения задания.

Рекомендуемая схема для следующей версии конвейера:

1. На подготовке извлечь изображения и привязки к пунктам, не отправляя их сразу модели.
2. Завершить текстовые этапы на профиле без `--mmproj`.
3. Одним этапом обработать все изображения на профиле с проектором. При 16 ГБ VRAM держать резидентным только один профиль.
4. Вернуть текстовый профиль лишь если после изображений остаётся текстовая перепроверка. Сохранять задачи и результаты до каждого переключения.
5. Раздельно хранить подпись профиля в ключе кэша ответов и в записи задачи; проверить восстановление после сбоя во время переключения.

Для переключения профилей `llama.cpp` документирует режим роутера с динамической загрузкой и выгрузкой моделей. При текущем прямом запуске через Context Guard потребуется согласовать роутер с ним либо перезапускать сервер на границе этапов. Выбор следует сделать по измеренному времени загрузки, выигрышу на текстовых запросах и числу изображений в контрольном наборе.
