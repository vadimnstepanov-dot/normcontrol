# Нормативные связи и трассировка комплекта

Портал остаётся общим рабочим пространством команды; доверенная LLM подключается через заменяемый endpoint. Нормативная база и проверенные рецензии уточняют контекст модели, не изменяя её веса.

## Редактор

Нормативная база → «Нормативные связи и трассировка». Выберите исходную карточку, целевую карточку и карточку, **обосновывающую саму связь**. Виды документов задаются данными. Отношения: детализирует, сохраняет ограничения, проверяет методом и критерием. Номер раздела — адрес для человека; ID карточки и точная версия — идентичность.

Выбор карточек открывает цитаты и исходное нормативное положение. LLM может предложить связи между 2–12 выбранными карточками; предложения не становятся подтверждёнными правилами. Куратор сохраняет условие применения, обязательность целевого документа и объяснение решения. Уверенность модели хранится отдельно от экспертного статуса. Изменения имеют историю и проверку версии; повтор одного запроса не создаёт новую редакцию.

Публикация закрепляет версии, хеши карточек и контекст профилей. Обработчик сверяет их с канонической базой и проверенными источниками. Если источник, родительское условие или карточка изменились, старое подтверждение не переносится молча. Публикация не заменяет экспертную проверку полноты.

## Исполнение

Новая проверка получает `trace_version=package-trace-9.1.6`. Старые проверки продолжаются с прежним снимком. Предыдущий обработчик не может принять новое поручение с трассировкой: контракт проверяется по возможностям исполнителя.

1. Фиксируются опубликованные связи и состав комплекта. Классификация подтверждается цитатой титула; неизвестный тип не исключается молча.
2. Вычисляется трёхзначная применимость по доказанным фактам. Неизвестная стадия → вопрос; доказанно ложное условие → «Не применяется».
3. Если обе стороны помещаются в бюджет, сравниваются совместно, затем независимо перепроверяются. Смысл, числа, единицы, направление границы, режим и критерий испытания входят в политику проверки.
4. Для больших документов выполняется полный последовательный сбор относящихся цитат. Итог сравнивает обе стороны вместе. Собранные цитаты **не являются доказательством глобального отсутствия**. Если все доказательства не помещаются, они не обрезаются: результат — вопрос с ограничением.
5. Нормативная связь с неподтверждённым основанием не даёт подтверждённого нарушения. Для доказанной цепочки нужны точные цитаты обеих сторон; ссылка в базе не заменяет фактическое исполнение.
6. Отсутствующий целевой документ — нарушение только при подтверждённом обязательном основании, доказанной применимости, определённых типах всех документов и отсутствии непрочитанных областей.

Отсутствие нормативной связи в базе показывается как ограничение охвата. Оно **не создаёт нарушение в комплекте**. Отсутствие понятия в одной части не доказывает отсутствие во всём комплекте.

## Матрица и отчёт

На странице проверки доступна матрица и списочное представление. Нажатие результата раскрывает версию связи, нормативную цитату и доказательства обеих сторон: документ, пункт/абзац или таблица, точная цитата. Фильтры отделяют доказанные цепочки, подтверждённые расхождения, предварительные выводы, вопросы и неприменимые связи.

В реестре замечаний появляются расхождения и вопросы. Word/Excel также содержат положительные и неприменимые решения матрицы, с основанием и адресами. Нормативный охват и число нарушений остаются разными показателями.

## Хранение, права, возобновление

`NormativeLink`/`NormativeLinkRevision` — версионированная конфигурация портала. Выпуск переносит проверенный снимок в канонический `publication_policy`; существующие снимки неизменны. Редактирование требует upload, подтверждение — publish, чтение — read соответствующей области. Матрица требует также доступа к пакету. Результаты трассировки сохраняются в задаче `trace.run` по каждой части; повторная доставка не вызывает успешную LLM-операцию снова. При паузе уже завершённые нормативные части и цитаты сохраняются. Общая очередь `model_turn` исключает конкуренцию text/vision на одном ресурсе GPU.

## Границы готовности

Проверенные автоматические сценарии и реальный прогон LLM не заменяют пользовательскую приёмку. Этап 10 использует независимый отложенный набор. Полный норматив с непроверенными областями нельзя объявлять готовым по небольшому контрольному фрагменту. Для связей между разными нормативными наборами требуется объединить источники в один публикуемый набор; редактор не обещает межнаборное редактирование.


## Контрольный прогон и приёмка

Для проверки 9.1.7 использованы реальные границы portal API, DOCX из точных фрагментов 1755-р, локальная Qwen3.8, сервис эмбеддингов и Qdrant в отдельной области. Контрольный файл явно отмечен как фрагмент, не заменяющий полный норматив. Вторая испытательная редакция добавляет искусственное требование и служит только проверке Diff, а не новой редакцией официального СТО. Такие данные нельзя переносить в рабочую нормативную область.

Классификация сохраняет доказанные титулом эквивалентные названия вида (полное название и сокращение) из настроенных профилей/связей. Неизвестная стадия не выводится из типа документа. Один нормативный атом может занимать обе стороны связи, если роли документов различаются; самоссылка в одной роли запрещена. LLM-предложения ограничены ID выбранных карточек и видами документов из профилей; категория «requirement» не считается видом документа.

Обрыв структурированного ответа по группе обязанностей приводит к делению группы; каждая подгруппа получает прежнюю полную область доказательств. Снимок и исходный план сохраняются. Завершённые подгруппы записываются с хешами в локальный журнал; повтор после сбоя использует их. Неделимое требование, невалидная цитата или незавершённая область остаются явной ошибкой/вопросом. Повтор не является сжатием исходных доказательств.

Смена редакции показывает также добавленные, изменённые и удалённые нормативные связи. Старые проверки закреплены за прежним выпуском. Сопоставление разных карточек по адресу требует ручной сверки; одинаковая формулировка не разрешает автоматически переносить экспертное подтверждение в другой источник/контекст.

Приёмочный маршрут: загрузить источник → дождаться разбора и анализа → изучить точные цитаты карточек и условия → подтвердить ясные карточки → создать/подтвердить связь с нормативным основанием → подготовить и опубликовать выпуск → запустить комплект → открыть результат ячейки матрицы и проверить обе стороны → выгрузить Word/Excel → загрузить новую редакцию → изучить Diff. Для неизвестной применимости, непрочитанной области и неопубликованного выпуска ожидается ограничение, а не подтверждённое соответствие.

Полнота выделения норм из всего источника требует независимой экспертной оценки. Большой 1755-р содержит явно сохранённые вопросы и не объявлен полным нормативным выпуском по успешному малому фрагменту. Пользовательская приёмка 9.1.7 и независимый этап 10 остаются отдельными воротами.

Готовый анализ источника сохраняется в `analysis-deliveries` перед удалённой передачей. Контрольная сумма связывает его с неизменным составом команды. Временный сетевой отказ повторяет доставку, а не смысловой анализ; промежуточные вопросы и статус `partial` не исчезают. Повторяются только идемпотентные операции. Нормативный источник с вопросами полноты по-прежнему не публикуется как полный: подтверждение отдельной карточки не закрывает вопрос полноты исходного блока. Для таких вопросов необходим отдельный экспертный маршрут с основаниями; массовая смена статуса не является доказательством.
