# Универсальная RAG: загрузка и структурное чтение (этап 3)

Новая нормативная область начинается пустой. Загрузка доступна через отдельное API v2 после включения `NORMCONTROL_KNOWLEDGE_V2=1`, миграции Django и запуска обработчика v2. Действующие проверки nc5 используют прежнюю очередь. Новый источник станет доступен для нормоконтроля после извлечения требований, индексации и публикации выпуска на следующих этапах.

## Загрузка и права

1. Создать область и набор через API этапа 2. Для загрузки нужна роль `contributor`, `curator` или `manager` либо собственная личная область.
2. `POST /normcontol/api/v2/normative-sets/{set_id}/sources/upload/` — multipart-поля `files` (1–20 файлов) и необязательное `supersedes` (ID прежнего источника, только для одного файла). Для сессии действует обычный CSRF. Допустимы DOCX, DOC и PDF, до 50 MiB каждый и до 200 MiB за группу. Если в группе один файл неверен, группа не регистрируется.
3. `GET .../sources/` — источники, состояния и сводки; `GET .../sources/{source_id}/` — отдельный источник. Состояния: `queued`, `processing`, `prepared`, `partial`, `error`. `partial` означает непрочитанные места. `prepared` означает завершённое структурное чтение, а не проверенную полноту нормативных требований.
4. `GET .../sources/{source_id}/coverage/?page=0` — полный журнал покрытия по 500 записей, с `total` и `has_next`. `GET .../sources/{source_id}/download/` — неизменённый исходный файл. Оба маршрута каждый раз проверяют право чтения. Для ошибки доступен `POST .../sources/{source_id}/retry/` с пустым JSON-телом; нужны права загрузки.

Имя файла не используется как путь хранения. Дубли SHA-256 в одном наборе возвращают прежний источник без новой команды или индексации; тот же файл в чужом наборе через API не обнаруживается. Новая редакция ссылается на прежний источник, но остаётся отдельным оригиналом. SHA-256 вычисляется потоково и сверяется после передачи обработчику. Файлы хранятся в частных каталогах портала и обработчика, без включения в образ.

## Передача и возобновление

Портал создаёт команду `source.ingest`. Обработчик с отдельным токеном получает аренду, скачивает оригинал только при действующей аренде и правах автора, продлевает аренду каждые 90 секунд и сохраняет оригинал по хешу. Он записывает `source_revision`, `fragment` и полный локальный журнал покрытия; ответ фиксирует в каноническом inbox до отправки на портал. Журнал передаётся порциями до 500 записей с хешем. Итоговый ответ принимается после сверки числа и хешей всех порций. Повтор после потери соединения идемпотентен. Постоянная ошибка конвертации или неверный файл сразу дают видимый статус `error`; временные ошибки имеют не более трёх попыток. Ручной повтор сохраняет тот же оригинал и заново передаёт журнал покрытия.

В DOCX сохраняются точный текст для цитаты отдельно от нормализованного поискового текста, путь заголовков, буквальный номер пункта при наличии, ссылки на другие пункты, таблицы, строки, столбцы, шапки, объединения, примечания и графические объекты. Автоматическая нумерация Word без внешней сверки помечается как требующая разбора. Непрочитанные рисунки, исправления и сомнительные пустые ячейки остаются в журнале. Изменение текста внутри раздела меняет хеш контекста, поэтому результаты изменённого раздела нельзя молча переиспользовать. Идентичная редакция не создаёт новых фрагментов.

DOC конвертируется во временную копию DOCX: в Linux-контейнере через LibreOffice, в нативной Windows через существующий скрипт экспорта Word. Исходный DOC сохраняется. PDF с текстовым слоем читается `pypdf`; локатор включает страницу. Если слой пуст, при доступных `pdftoppm` и `tesseract` с языками `rus+eng` выполняется OCR. Пустая или неуспешная страница явно считается непрочитанной. OCR-текст помечается для визуальной сверки. Табличная структура PDF не считается достоверно восстановленной и обозначена в журнале. Классификация по титульному тексту даёт тип только при однозначном признаке; иначе возвращается `unknown` с необходимостью явного выбора профиля на следующем этапе.

## Ограничения

Старый каталог не импортируется; LLM и индексы не участвуют в структурном чтении. Семантическое выделение обязанностей и зависимостей относится к этапу 4, индексы и выпуск — к этапу 5. Пользовательский экран загрузки и общая рабочая панель относятся к этапу интерфейса; сейчас загрузка доступна через API. Промышленная миграция и запуск контейнеров на текущем хосте не выполнялись: Docker отсутствует.
