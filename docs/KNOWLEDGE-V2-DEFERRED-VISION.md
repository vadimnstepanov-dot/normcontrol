# Изображения в конце нормативной проверки

Планировщик `context-budget-v4` сохраняет порядок: классификация и выбор
применимых требований → текст → связи комплекта → изображения.
Режим закрепляется при создании проверки; старые задания не перепланируются.

## План и доказательства

Из DOC/DOCX извлекаются изображения с адресами всех вхождений. Одинаковые
бинарные изображения проверяются один раз с окружением всех вхождений.
Многостраничные Visio/метафайлы разбиваются на страницы после конвертации.
В PDF включаются страницы с изображениями, векторными схемами или без текста.
Ошибки конвертации и отсутствие применимых требований показываются отдельно;
такие области не считаются проверенными. Чтение бинарных файлов не вызывает LLM.

К каждому изображению прикладываются применимые требования со всеми условиями,
нормативным контекстом и точными цитатами окружающего текста. Несколько требований
объединяются в один запрос, если помещаются в фактический контекст модели.
Резервируются 8192 токена для изображения, ответ и запас для независимой
перепроверки. Непоместившееся одиночное требование становится ограничением,
а не обрезается. После текста и связей модель получает изображения.

Визуальный вывод сохраняет хеш исходного объекта, все вхождения, страницу,
описание видимого факта и координаты области. Возможные нарушения проходят
отдельную перепроверку с тем же изображением и полными условиями. Они остаются
предварительными до экспертной проверки. Обработка рисунков не снимает автоматически
ограничения полноты документа; отсутствие детали на рисунке не доказывает её
отсутствия во всём документе. Нечитаемые надписи и неясные стрелки — вопросы.

## Профили модели

`text` запускает сервер без `--mmproj`. `vision` использует совместимый проектор.
Весь завершающий визуальный этап занимает один эксклюзивный ход общей очереди:
одно подключение проектора перед этапом и возврат к `text` после него, в том числе
при паузе или ошибке. Это требует перезагрузки модели; горячее подключение
проектора в работающий llama-server здесь не предполагается. Смена профиля
включает штатную остановку, ожидание освобождения процесса и проверку готовности.

Для управляемого локального сервера:

1. Настройте доверенный шлюз и его защищённый `POST /model/profile`.
2. В закрытом конфиге шлюза включите `allow_model_profiles: true`.
3. Настройте запуск по переменной `NORMCONTROL_LLM_PROFILE=text|vision`.
   Пример Windows: `deploy/local-llm/start-llama.cmd.example`.
4. Подключите `compose.model-profiles.yaml` к обоим рабочим сервисам.
5. Активируйте новый образ только после завершения старых проверок и доставки
   их результатов. Пауза старого прогона сама по себе не разрешает смену
   закреплённого профиля. Сохраните старый образ до закрытия этих прогонов.

Шлюз проверяет авторизацию, разрешённый адрес и фиксированные имена профилей;
произвольные команды, пути и параметры модели через этот маршрут не принимаются.
Не включайте адаптер для облачного сервера, который не поддерживает этот протокол.
Для внешнего мультимодального API оставьте адаптер выключенным: визуальная часть
может работать через совместимый API, но отключение его проектора не гарантируется.

## Продолжение и статистика

Каждое изображение/пакет требований имеет отдельную контрольную точку. Продолжение
использует сохранённые результаты, без повторения завершённых изображений.
Панель показывает текущий этап и число визуальных заданий; отчёт содержит
визуальные ограничения и отдельные технические ошибки. Время, usage и фактические
timings визуальных запросов сохраняются отдельно от текстовых скоростей.

Переключения и остановки проверяются на изолированных заменителях сервера.
До первого реального прогона после безопасной активации это не является замером
качества vision-модели, фактического ускорения или расхода VRAM на изображениях.
