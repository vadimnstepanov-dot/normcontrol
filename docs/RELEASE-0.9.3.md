# Выпуск 0.9.3

Выпуск объединяет подготовку и управление ресурсами проверок, сокращает повторные измерения при планировании и восстанавливает автоматический запуск модели для очереди.

## Изменения

- Новые совместимые обработчики используют общий конвейер `pipeline-v1`: подготовленные документы, зависимости этапов и очередь ресурсов. Правила языковой, логической, нормативной и междокументной проверки сохраняются отдельно.
- Подготовка на CPU допускается одновременно с работой GPU. По умолчанию доступны две CPU-задачи и одна GPU-задача; допуск зависит от измеренной свободной RAM и оценок памяти активных задач. Резерв системы — 4096 МиБ; сериализованный кэш документов ограничен 1024 МиБ и дополнительно сокращается при недостатке памяти. Эти оценки не являются жёсткими ограничениями памяти процессов ОС.
- Канонические документы повторно используются нормативным этапом с проверкой исходных контрольных сумм. Подготовленные материалы передаются потоково через авторизованный шлюз.
- Подсчёт токенов кэшируется по сигнатуре модели и точному запросу. Планировщик ограничивает повторные измерения и подбор для больших наборов требований. Визуальный этап ожидает завершения текстовых проверок перед переключением модели.
- Появление задачи запускает модель автоматически. Команда остановки учитывается; автоматический запуск модели не возобновляет ранее приостановленные пользователем проверки.
- При восстановлении незавершённой проверки обработчик проверяет готовность модели. Старый закреплённый план продолжает выполняться отдельно от нового конвейера.
- Интерфейс отображает состояние нормативного этапа и ожидание свободной памяти при совместном выполнении проверок.

## WSL

Для установки с нормативными обработчиками в WSL предусмотрен `scripts/keep-wsl-alive.ps1`. Он удерживает дистрибутив активным через фоновый процесс `sleep infinity`, чтобы завершение коротких обращений не останавливало Docker. Пример: `powershell -File scripts/keep-wsl-alive.ps1 -Distro NormControl`.

Если перед запуском `scripts/start-local.ps1` задана переменная `NORMCONTROL_KNOWLEDGE_DISTRO`, помощник запускается автоматически для указанного дистрибутива. Сам помощник не устанавливает Docker и не изменяет его настройки. Для остановки этой фоновой сессии можно использовать штатную команду завершения соответствующего дистрибутива WSL после остановки проверок.

## Проверка и ограничения

Тесты запускаются командой `python tools/test_release.py` в окружении из `requirements-test.txt` и `requirements-test.lock`. В обязательный набор включены тесты очереди ресурсов, шлюза, автоматического запуска модели и восстановления обработчика.

Локально проверены 816 тестов: 815 успешно, один тест живой модели штатно пропущен. Проверки зависимостей, синтаксиса JavaScript и помощника WSL прошли.

Существующие проверки не переводятся автоматически на новый конвейер и не перепланируются. Старый нормативный обработчик необходимо сохранить для возобновления закреплённых проверок; для нового конвейера нужны совместимые версии портала, локального обработчика, шлюза и нормативного обработчика.

Образ нормативного обработчика собирается из исходников выпуска: `docker build -f deploy/knowledge-v2/worker.Dockerfile -t normcontrol/review-worker:0.9.3 .`. Дополнительный файл `deploy/knowledge-v2/compose.review-v5.local-llm.yaml` предназначен для установки со шлюзом доверенной локальной модели и явно настроенным сертификатом. Пользовательская конфигурация и образы контейнеров не публикуются в этом GitHub-выпуске.

Сокращение служебных запросов проверено отдельно; ускорение полного цикла на реальном комплекте документов пока не измерено. Выполнение задания и отсутствие замечаний не доказывают полного раскрытия каждого функционального требования. Пользовательские документы, нормативная база, результаты проверок, модели и учётные данные в выпуск не входят.
