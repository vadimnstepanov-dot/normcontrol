# Рабочее место эксперта (9.1.4)

В нормативной базе нажмите **«Рабочее место эксперта»**. Выберите область и профиль, затем строку требования. Слева открывается нормативный источник с точными цитатами, справа — карточка. На телефоне панели доступны вкладками «Карточка» и «Источник».

## Возможности

- Профили с наследованием, фильтры по разделу, типу, экспертному решению; поиск по формулировке, источнику и адресу. Отдельный режим глоссария. Выдача по 25 строк с сервера.
- Условия применения/согласования и исключения имеют собственные ссылки на основания. Кнопка «Показать основание» выделяет цитату. Оригинал доступен для скачивания, растровые изображения DOCX — для просмотра.
- Редактируются формулировка, тип, термин, пояснение применимости, условия и исключения. Новые условия связываются с существующими проверенными цитатами; подмена оригинального текста и смещений через редактор запрещена.
- Сохранение, подтверждение, отклонение, разделение и объединение требуют обоснования. Подтверждается конкретная версия; следующая правка снимает подтверждение с новой версии. Прежние решения остаются в истории.
- При разделении сохраняются все атомы и общие условия, при ручной декомпозиции явно выбирается AND/OR. Объединение сохраняет все основания и обязательства; несовместимые области, типы и альтернативные группы не объединяются молча.
- Наследованные карточки доступны для чтения, редактирование выполняется в профиле-владельце. Переход к владельцу виден в карточке.
- Состояние фильтров, страницы и выбранной карточки сохраняется в адресе. Есть переход к следующей непроверенной карточке (Alt+↓), видимый фокус, светлая и тёмная темы.

Оценка модели, решение эксперта, применимость и публикация — разные признаки. Экспертное подтверждение карточки не означает полноту анализа всего источника.

## Владение данными и права

Портал хранит индекс карточек для интерфейса и намерение пользователя. Каноническая экспертная редакция сохраняется локальным `expert-worker` в той же базе, где находятся исходные записи. Он не вызывает LLM, не обращается к GPU и не ждёт завершения длительного анализа. Портал показывает новую версию после подтверждения записи обработчиком.

На каждом действии проверяются область доступа, роль, ожидаемая версия, идентификатор повторной отправки и отсутствие конкурирующей правки. Обработчик повторно проверяет права непосредственно перед записью. Читатель может открыть источник, эксперт — менять карточки и принимать решения. Изменение состава ролей не входит в этот экран.

Новые таблицы портала: `ExpertCard`, `ExpertCardRevision` (миграция `0009_expert_workspace`). Новая каноническая сущность: `expert_card`. Обновление не меняет оригиналы источников и существующие снимки проверок. `knowledge_expert_backfill` индексирует только ранее принятые результаты анализа; не запускает извлечение и не перезаписывает экспертные версии.

## Установка Windows/WSL2 и Linux

Далее команды выполняются из каталога проекта в Linux либо WSL2. Путь канонических данных и токен уже должны быть настроены в `deploy/knowledge-v2/.env` по основной инструкции. У службы эксперта тот же пользователь тома (UID 65532), что у штатного обработчика. Не делайте базу общедоступной для записи.

1. Создайте резервную копию базы портала и канонической базы штатным механизмом SQLite backup. Сохраните код и конфигурацию. Не копируйте открытый SQLite-файл без его WAL.
2. Установите код портала и общего модуля `knowledge_v2`. В окружении портала выполните:

```sh
python manage.py migrate --noinput
python manage.py knowledge_expert_backfill
python manage.py check
python manage.py collectstatic --noinput
```

3. Перезагрузите веб-процесс с завершением текущих HTTP-запросов. Для Gunicorn используйте HUP его master-процессу. LLM, анализатор и индексатор перезапускать не требуется.
4. Соберите и запустите отдельную службу:

```sh
docker compose --env-file deploy/knowledge-v2/.env \
  -f deploy/knowledge-v2/compose.yaml \
  -f deploy/knowledge-v2/compose.expert.yaml \
  build expert-worker
docker compose --env-file deploy/knowledge-v2/.env \
  -f deploy/knowledge-v2/compose.yaml \
  -f deploy/knowledge-v2/compose.expert.yaml \
  up -d --no-deps expert-worker
```

Если используется `compose.local-llm.yaml`, перед `compose.expert.yaml` добавьте этот существующий override. Не выводите содержимое `.env` в журналы. Служба не публикует сетевые порты, ограничена 0,5 CPU / 256 MiB и обращается к порталу исходящим HTTPS.

5. Проверьте страницу `/normcontol/knowledge/expert/`, выдачу списка и появление полного текста источника после выбора реальной карточки. Само чтение не должно изменять номер версии. Проверьте доступность CSS/JS и состояние контейнера.

При откате остановите только `expert-worker`, восстановите прежний код и перезагрузите портал. Добавленные таблицы/канонические версии оставьте для восстановления; не возвращайте резервную копию рабочей базы поверх новых пользовательских решений. Полный откат данных требует отдельного окна обслуживания.

## API

Все пользовательские запросы требуют сессии и доступа к области; изменения — CSRF и `Idempotency-Key`.

| Путь после `/normcontol/api/v2/expert/` | Назначение |
|---|---|
| `catalog/` | Доступные области и дерево профилей |
| `cards/` | Фильтры `scope`, `profile`, `section`, `type`, `status`, `q`, `glossary`, `page` |
| `cards/{id}/` | Карточка; POST-действия `inspect`, `edit`, `confirm`, `reject`, `split`, `merge` |
| `cards/{id}/history/` | История по 30 записей |
| `cards/{id}/versions/{number}/` | Содержимое сохранённой версии |
| `sources/{id}/images/` | Растровые оригиналы из DOCX, с проверкой прав |

Изменения передают `expected_revision`; 409 означает конфликт версии/незавершённое действие. Ответ 202 подтверждает постановку команды, а не завершение сохранения. Исходные цитаты не являются редактируемым полем.

## Границы этапа

Начиная с этапа 9.1.5 экспертные версии включаются в закреплённые нормативные выпуски. Подготовка проверяет точные версии карточек, публикация не заменяет подтверждение эксперта. Наследование, локальные уточнения, Diff и доверие выводам описаны в [KNOWLEDGE-V2-PUBLICATION.md](KNOWLEDGE-V2-PUBLICATION.md).

Поиск рабочего места эксперта текстовый; семантический поиск работает по опубликованным выпускам. Междокументная матрица трассируемости относится к этапу 9.1.6.

Встроенный просмотр изображений ограничен безопасными растровыми вложениями DOCX. Полные PDF/DOC и прочие форматы оригинала открываются через скачивание; редактор не выполняет повторный OCR.
