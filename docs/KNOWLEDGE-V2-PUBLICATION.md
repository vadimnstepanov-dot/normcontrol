# Нормативные выпуски, наследование и доверие

Этап 9.1.5 добавляет к рабочему месту эксперта закреплённый состав исполняемых требований. Исходные карточки модели, экспертные версии и публикация — отдельные сущности. Сохранение или подтверждение карточки не публикует выпуск.

## Работа в интерфейсе

1. Завершите выделение требований из нормативных источников. Незавершённый анализ не разрешает подготовку выпуска.
2. Проверьте карточки, условия и профили. Необязательно подтверждать все карточки: неподтверждённые нормы могут давать только предварительные замечания.
3. Нажмите «Подготовить выпуск». Закрепляются версии источников, карточек и иерархии профилей; индекс строится локально.
4. Откройте «Состав и изменения». Вкладка сравнения показывает прежний и новый текст, условия, исключения, зависимости, версии профилей, утрату актуальности подтверждений. Ссылки открывают конкретную версию карточки только для чтения.
5. Опубликуйте проверенный выпуск. Если после подготовки изменились карточки или профили, подготовьте новый выпуск. Для новых проверок выбираются опубликованные выпуски. Старые проверки продолжают использовать закреплённый снимок.

## Наследование и локальные уточнения

Профиль может наследовать несколько профилей. Один норматив и его атомарная обязанность не дублируются при наследовании по нескольким ветвям. Применимость проверяется по условиям всей соответствующей цепочки; неподходящая независимая ветвь не отменяет подходящую.

Унаследованная карточка доступна для чтения. «Уточнить для этого профиля» создаёт отдельную локальную карточку: пояснение, дополнительное ограничение, исключение или конфликт. Родительская норма сохраняется. Уточнение содержит ссылку на родительскую версию, основание и причину.

Исключение может снять применение родительской нормы только после актуального экспертного подтверждения, при проверенных источниках и доказанном условии исключения. Неизвестное условие, изменившийся родитель или неразрешённый конфликт блокируют подтверждённый вывод. Число уверенности модели не заменяет доказательства.

При разделении составной нормы сохраняется логика «все условия» / «любое условие». Невыполненная альтернатива сама по себе не становится нарушением всей группы.

## Доверие и обновления

Подтверждение закрепляет смысл, источники и нормативный контекст. Изменение условий профиля или связанной нормы делает подтверждение устаревшим в новом выпуске, даже если текст самой карточки прежний. Старый выпуск и отчёт не переписываются. Проверка контекста намеренно консервативна: изменение связанной нормы может потребовать повторной сверки соседних карточек.

Отдельно сохраняются оценка модели 0–1, решение эксперта и технические блокировки. Непроверенное происхождение, неоднозначный смысл, нераскрытая зависимость или неполный критичный контекст запрещают подтверждённое замечание. Публикация набора не отменяет эти ограничения.

Сравнение использует постоянное происхождение карточки, затем уникальное совпадение смысла в явно заданной семье редакций. Совпадение только адреса — предположение, требующее проверки; неоднозначные совпадения не склеиваются. Две редакции одного источника нельзя одновременно включить в один нормативный выпуск.

## Устройство

Портал закрепляет `curation` в команде подготовки. Локальный обработчик сверяет точные канонические версии, создаёт исполняемые карточки, профили и запись `publication_policy` с перечнем `effective_refs`. Исходные записи остаются в выпуске для происхождения; поиск и исполнитель не используют их как второй экземпляр нормы. Разрешённые зависимости переносятся на исполняемую карточку с сохранением точных ссылок.

Материал выпуска передаётся на портал ограниченными порциями с контрольными суммами и защитой от повторной доставки. Списки состава и изменений выдаются постранично. При публикации повторно проверяется неизменность выбранных версий. API и HTML сохраняют проектные права доступа.

Интерфейс работает на VPS; извлечение, каноническая база, индексирование, embeddings и модель остаются на вычислительном хосте. Используются существующие кроссплатформенные Docker-сервисы; отдельная тяжёлая служба для сравнения не нужна. Экспертный обработчик не вызывает LLM.

## Проверки и пределы этапа

Проверяются: наследование ромбом, изменение родительского условия, точность версий, запрет неподтверждённого исключения, неизвестная применимость, разделённые альтернативы, разграничение прав, неизменность снимка и различение предварительных/подтверждённых замечаний. Наборы `knowledge.test_publication` и `knowledge_v2.tests.test_curation` дополняют регрессионные тесты.

Это не подтверждение полноты автоматического извлечения всех требований из любого СТО. Полная междокументная матрица трассируемости относится к следующему подэтапу 9.1.6; нагрузочная приёмка большого корпуса — к этапу 10. Правила поиска не заменяют сплошной реестр применимых обязанностей.
