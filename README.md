# Нормоконтроль технических документов

Локальная система пакетного нормоконтроля документов Word по требованиям СТО. Она извлекает структуру и факты из документа, проверяет грамотность, техническую и междокументную логику, подбирает применимые требования из локальной базы и формирует отчёт с проверяемыми цитатами и адресами замечаний.

Система рассчитана на работу с локальной LLM через OpenAI-совместимый API `llama.cpp`. Документы и модель остаются на компьютере обработчика. Отдельный Django-портал можно разместить на маломощном сервере: он хранит очередь и отчёты, а вычисления выполняет локальный worker.

## Возможности

- пакетная проверка `.docx` и `.doc`;
- классификация документа и разбиение по его логической структуре;
- проверки грамотности, технической логики, требований СТО и связей между документами;
- проверка оформления по инструкции по делопроизводству, если она добавлена в нормативную базу;
- точные цитаты из проверяемого документа и нормативного источника;
- адресация по номеру пункта и номеру абзаца от заголовка;
- очередь, пауза, отмена, повторный запуск и удаление пакетов;
- текущие замечания, прогресс, прогноз завершения и метрики производительности;
- локальный запрет сна Windows на время активной проверки;
- портал с авторизацией, саморегистрацией пользователей `RZDTECH/…` и административными функциями.

## Архитектура

```text
Word-документы ──> локальный worker ──> llama.cpp / локальная LLM
                         │
                         ├── локальная база требований СТО
                         ├── извлечённая структура и факты
                         └── проверяемые замечания и отчёты
                         │
                  локальный UI или HTTPS-портал
```

`sto_rag/nc5` содержит движок проверки и локальный интерфейс. `normcontrol-web` содержит портал очереди. Портал не выполняет LLM-инференс и может работать на сервере с небольшим объёмом памяти.

## Быстрый запуск на Windows

Требуются Python 3.11 или 3.12, актуальная сборка `llama.cpp`, локальная GGUF-модель и Microsoft Word для поддержки старого формата `.doc` и сверки автоматической нумерации.

```powershell
git clone https://github.com/vadimnstepanov-dot/normcontrol.git
cd normcontrol
powershell -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1
Copy-Item .\config\config.example.json .\sto_rag\data\nc5\config.json
$env:PYTHONPATH = "$PWD\sto_rag"
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py probe
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py serve
```

Откройте `http://127.0.0.1:8096`. Конкретный адрес и одноразовый токен также выводятся в консоль при запуске.

Перед первым запуском поместите разрешённые к использованию исходные файлы СТО `.docx` в корень проекта и соберите каталог:

```powershell
powershell -ExecutionPolicy Bypass -File .\sto_rag\verify_word.ps1
.\.venv\Scripts\python.exe .\sto_rag\rag.py build
$env:PYTHONPATH = "$PWD\sto_rag"
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py catalog
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py catalog-audit
```

Подробная настройка модели, нормативной базы, портала и worker приведена в [INSTALL.md](INSTALL.md).

## Командная строка

```powershell
$env:PYTHONPATH = "$PWD\sto_rag"

# Проверка одного или нескольких связанных документов
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py run `
  "C:\Documents\ТЗ.docx" "C:\Documents\ОИТ.docx"

# Состояние всех заданий или одного задания
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py status
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py status <job-id>

# Повторное продолжение и экспорт отчёта
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py resume <job-id>
.\.venv\Scripts\python.exe .\sto_rag\normcontrol_v5.py export <job-id>
```

Флаги `--no-language`, `--no-sto` и `--no-logic` отключают соответствующий проход для конкретного запуска.

## Что не входит в репозиторий

- тексты СТО, инструкции и другие нормативные документы;
- документы пользователей и сформированные отчёты;
- веса моделей GGUF;
- рабочие базы данных, токены, ключи и конфигурация конкретной инфраструктуры.

Добавляйте только те нормативные источники, на использование которых у вас есть право. `.gitignore` предотвращает случайную фиксацию типовых документов, моделей и рабочего состояния, но перед публикацией изменений всё равно проверяйте `git status`.

## Проверка изменений

Полный набор тестов движка использует предварительно собранный тестовый каталог. Поэтому сначала выполните шаги подготовки RAG или подключите отдельные тестовые нормативные источники, которые разрешено хранить в вашей среде.

```powershell
$env:PYTHONPATH = "$PWD\sto_rag"
.\.venv\Scripts\python.exe -m unittest discover -s .\sto_rag\nc5\tests

$env:APP_DEBUG = "1"
$env:APP_DATA = "$env:TEMP\normcontrol-web-tests"
.\.venv\Scripts\python.exe .\normcontrol-web\manage.py test portal
```

Автоматический отчёт не заменяет решение специалиста по нормоконтролю. Отсутствие замечаний при незавершённых или неподтверждённых проходах не означает соответствие документа.
