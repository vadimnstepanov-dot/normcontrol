# Основной обработчик NormControl 1.0.0 в Docker/WSL

Этот комплект переносит основной обработчик, подготовку, планировщики, очередь и шлюз в Linux-контейнеры. GPU-модель, Microsoft Word и аппаратная телеметрия остаются в Windows. Правила каждого направления проверки сохранены; платформа подключается адаптерами `sto_rag/native_core`.

## Компоненты

| Сервис | Назначение | Лимит Compose |
| --- | --- | --- |
| worker | Подготовка, планирование, выполнение и обмен с порталом | 2 ГиБ, 2 CPU |
| gateway | Общая очередь SQLite, допуск CPU/GPU, TLS, Windows-мост | 384 МиБ, 0,5 CPU |
| api | Локальный API и интерфейс | 768 МиБ, 0,5 CPU |
| Knowledge v2 | Отдельные индекс, подбор и нормативные обработчики | [Своя конфигурация](../knowledge-v2/INSTALL.md) |
| Windows | Модель, Word, аппаратные показатели | Вне этих лимитов |

Данные по умолчанию — `/opt/normcontrol/native-core/data` на Linux-диске, внутри контейнеров `/data/nc5`. Не храните SQLite на `/mnt/c` или SMB. Очередь `pipeline.sqlite3` принадлежит шлюзу; клиенты обращаются к ней по API.

Две CPU-задачи могут идти одновременно с одной GPU-задачей при наличии RAM. Резерв Windows — 2048 МиБ, дополнительный резерв Linux — 512 МиБ, кэш документов не более 1024 МиБ и дополнительно ограничивается памятью контейнера. Это не изменяет лимит WSL; учитывайте также модель и контейнеры Knowledge v2.

## Предварительная подготовка

1. Установите WSL 2, Linux-дистрибутив с systemd, Docker Engine и Compose plugin. Для обычного Linux этот комплект тоже собирается, но его Windows-мост всё равно нужен.
2. В Windows установите зависимости по [INSTALL-WINDOWS.md](../../INSTALL-WINDOWS.md), Microsoft Word и совместимый сервер модели. Модель слушает `127.0.0.1:8082`; её процесс запускается и контролируется на Windows.
3. Настройте HTTPS-портал и приватный worker.env по [config/worker.env.example](../../config/worker.env.example). Нормативная база устанавливается отдельно.
4. Подготовьте сертификаты, токены и закрытые конфигурации вне Git. Имена/IP endpoint должны присутствовать в SAN сертификата. Не отключайте проверку TLS.

## Сборка из исходников

Из корня клона тега 1.0.0, в WSL/Linux:

```sh
docker build -f deploy/knowledge-v2/worker.Dockerfile -t normcontrol/review-worker:1.0.0 .
docker build -f deploy/native-core/Dockerfile --build-arg CORE_BASE=normcontrol/review-worker:1.0.0 -t normcontrol/native-core:1.0.0 .
docker run --rm --entrypoint python normcontrol/native-core:1.0.0 -m pip check
docker run --rm --entrypoint python normcontrol/native-core:1.0.0 -c 'import nc5.engine, knowledge_v2.ingest, native_core.runtime'
```

Это локальные теги: опубликованные образы из Docker Hub не требуются. Для принятого развёртывания закрепите полученный image ID/digest. Не заменяйте работающий контейнер до checkpoint и резервной копии.

## Файлы конфигурации

Скопируйте в `/opt/normcontrol/native-core` файлы compose.yaml и .env.example; переименуйте второй в .env. Постоянные данные должны быть доступны UID 65532:

```sh
sudo install -d -o 65532 -g 65532 -m 700 /opt/normcontrol/native-core/data
sudo install -d -o root -g 65532 -m 750 /opt/normcontrol/native-core/secrets
```

Создайте следующие **рабочие**, а не демонстрационные файлы:

| Каталог | Файлы |
| --- | --- |
| Linux secrets | gateway.json, gateway.crt, gateway.key, queue.token, host.token, worker.env |
| Windows RuntimeDirectory | worker.env |
| Windows RuntimeDirectory/native-core | host-bridge.json, forwarder.json, monitor.json, сертификат/ключ и закрытые файлы токенов |

Примеры JSON находятся рядом с этой инструкцией. Значения `192.0.2.*`, пути и `REPLACE_*` — заглушки, их нужно заменить. queue.token должен совпадать с token в gateway.json, host.token — с токеном Windows-моста. worker.env содержит отдельную авторизацию портала. Закройте доступ к файлам; Linux-пользователь 65532 должен читать смонтированные секреты, остальные пользователи — нет.

Сертификат `gateway.crt` используется также для доверия к Windows-мосту. Используйте согласованную цепочку доверия: bundle должен содержать необходимый сертификат/издателя, а серверный файл — свою цепочку; проверяйте оба endpoint. При самостоятельной настройке общего сертификата его SAN должен включать оба имени/IP и имя Docker-сервиса gateway.

В .env укажите:

- NORMCONTROL_CORE_IMAGE, пути DATA и SECRETS;
- NORMCONTROL_QUEUE_ENDPOINT — TLS-адрес очереди, доступный контейнерам, например `https://gateway:8098`;
- NORMCONTROL_HOST_ENDPOINT — TLS-адрес Windows-моста;
- адреса привязки шлюза и API.

Пример по умолчанию публикует порты только на loopback Linux. **Для пересылки из Windows по IP WSL** установите NORMCONTROL_QUEUE_BIND=0.0.0.0 и NORMCONTROL_API_BIND=0.0.0.0 в WSL, ограничьте firewall и allowed_networks фактическими доверенными клиентами. Windows-forwarder публикует API 8096 только на 127.0.0.1; TLS-порт 8098 — только на выбранном интерфейсе с точным списком разрешённых клиентов. Не открывайте эти порты для всего интернета.

Для native worker сохраните config.json в DATA: параметры модели и контекста из [примера](../../config/config.example.json), endpoint Windows-моста, имя реально загруженной модели. Настроенный API key для моста вводится адаптером из файла host.token. Не копируйте в контейнер Windows-пути исходников: документы передаются порталом, а локальный импорт разрешается отдельным списком.

## Windows-мосты

- **host_bridge**: физическая RAM, ограниченные API модели, чтение DOC, адреса и экспорт Word. Макросы и обновление внешних связей отключены, исходник открывается только для чтения, хэши входа и результата проверяются.
- **forwarder**: пересылка байтов портов 8098 и 8096 в WSL, адрес которой обновляется. TLS завершается в Linux-шлюзе.
- **windows_monitor**: CPU/GPU/RAM Windows, состояние Linux-очереди и управление моделью. Остановка модели ждёт освобождения GPU-билетов и сохраняет checkpoint.
- **sleep_guard**: предотвращает сон при свежем сигнале активной проверки.

DOC читается Word как XML-части в памяти; промежуточный DOCX не создаётся. Выгрузка сохраняет DOC → DOC, DOCX → DOCX. Прежние правки и примечания остаются. Непроверенные диапазоны, поля и неоднозначные изменения не заменяются по предположению; ограничения записываются в отчёт. Word-операции ограничены тайм-аутом, ошибки не выдаются за отсутствие нарушений.

`import_files` по умолчанию пуст. Добавляйте только явно разрешённые исходники; мост не предоставляет доступ к произвольным папкам Windows. Новые пользовательские документы загружаются через закрытый портал.

## Запуск

Установите [normcontrol-core.service](normcontrol-core.service) в systemd, сохранив фактический WorkingDirectory. Не включайте второй владеющий очередью Windows-worker одновременно с native core. Настройте маркер и Windows-запуск по [INSTALL-WINDOWS.md](../../INSTALL-WINDOWS.md#15-основной-обработчик-в-wsldocker).

Сначала запустите host_bridge и модель; затем:

```sh
cd /opt/normcontrol/native-core
docker compose --env-file .env config --quiet
docker compose up -d
docker compose ps
docker compose logs --tail 30
```

Образы работают без root, с файловой системой только для чтения и writable-каталогами DATA и /tmp. Секреты монтируются только для чтения. Health-check шлюза использует endpoint из .env, а не адрес конкретной рабочей станции.

Проверьте healthy всех трёх контейнеров, heartbeat на портале, учебную проверку DOCX и отдельно DOC/Word. Для Knowledge v2 подтвердите применимость требований и полноту источников отдельно от health.

## Плановые работы и обновление

До остановки приложения выполните в его рабочем окружении:

```sh
python manage.py planned_maintenance on --minutes 15 --message 'Обновляем обработчик и очередь NormControl.'
python manage.py planned_maintenance status
```

Страница возвращает HTTP 503, содержит срок и обновляется каждые 30 секунд. Рабочие API и статика продолжают обслуживаться. При задержке повторите on с новой оценкой; после проверки — `planned_maintenance off`. Страница не выключается автоматически по истечении срока.

Для доступности при остановленном Django установите [maintenance.caddy](maintenance.caddy) **внутри** существующего handle /normcontol/*, перед reverse_proxy, и задайте MAINTENANCE_PUBLIC_DIR=/var/lib/normcontrol-notice. Веб-сервер продолжает работать, отдавая только публичную страницу; документы он не раскрывает.

Перед сменой контейнеров вызовите /control/native/pause с заголовком X-Core-Control-Token через авторизованный шлюз и сохраните возвращённый token владения. Дождитесь checkpoint и отсутствия running GPU-билетов. Сделайте согласованную копию актуальных данных и SQLite, обновите контейнеры, проверьте health, затем /control/native/resume с тем же token. Более поздняя пауза пользователя имеет приоритет. При несовместимости старого плана не подменяйте его хэш; сохраните прежний результат и запустите отдельную совместимую проверку.

## Откат и ограничения

Сохраняйте предыдущие image ID и актуальную копию данных. Не накладывайте старую базу поверх новых результатов. Перенос обратно в Windows требует остановки единственного владельца очереди, согласованной копии **текущих** Linux-данных, восстановления путей и проверки хэшей/идентификаторов до снятия маркера wsl-core-active.json.

Прямой DOC и Word требуют Windows с Word. Перенос в контейнер не ускоряет саму GPU-модель и не подтверждает полноту замечаний. Синтетические тесты и сборка образа не заменяют проверку всей установки, сертификатов, GPU и Word после перезагрузки.
