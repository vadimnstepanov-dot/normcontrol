# Сервисы нормативной базы v2

**Актуальная инструкция:** [установка Windows/WSL2 и Linux, резервирование, восстановление, обновление и откат](INSTALL.md). Для эксплуатации и полного списка обработчиков используйте `INSTALL.md` и процедуру `ops.py`.

Эта конфигурация запускается на локальном компьютере обработчика. Без дополнительных профилей работают Qdrant, CPU-сервис эмбеддингов и построитель индекса. Профиль `worker` добавляет загрузку и анализ нормативов через защищённый API портала. Профиль `portal` предназначен для изолированного локального испытания Django, он не заменяет действующий портал VPS.

Данные новой RAG начинаются с пустого каталога. Старый каталог, проверки и рецензии не импортируются. Публикация чернового нормативного источника требует отдельного подтверждения полноты. `NORMCONTROL_KNOWLEDGE_V2` включается при согласованном переключении портала. На текущем хосте новая база уже включена для ручной приёмки; это не завершение этапа 10.

## Запуск на Windows/WSL2 или Linux

На Windows используется отдельный дистрибутив Ubuntu под WSL2 и Docker Engine внутри него. На Linux команды Docker Compose те же. Скопируйте `.env.example` в `.env` рядом с `compose.yaml`, укажите абсолютные **Linux**-пути `EMBEDDING_CACHE_PATH` и `KNOWLEDGE_DATA_PATH`, загрузите модель E5 заранее, задайте проверенный digest Qdrant. Для нового набора должен использоваться каталог, отличный от данных старой RAG. Файл `.env` не включайте в Git; задайте ему права только владельца. Оба локальных сервиса, пишущих в каноническую базу, работают под UID 65532; этот пользователь должен владеть `KNOWLEDGE_DATA_PATH`.

```bash
docker compose -p knowledge-v2 -f deploy/knowledge-v2/compose.yaml --env-file deploy/knowledge-v2/.env up -d --build qdrant embeddings index-worker
docker compose -f deploy/knowledge-v2/compose.yaml --env-file deploy/knowledge-v2/.env ps
```

Порты Qdrant `127.0.0.1:6333` и эмбеддингов `127.0.0.1:8109` доступны только на локальном компьютере. Проверка: `curl http://127.0.0.1:6333/healthz` и `curl http://127.0.0.1:8109/health`. У индексатора и Qdrant также есть проверки здоровья Docker. Контейнерные журналы ограничены тремя файлами по 10 МБ на сервис.

## Подключение обработчика к порталу

На портале должны быть применены миграции v2, установлен `NORMCONTROL_KNOWLEDGE_V2=1` и задан отдельный случайный токен `NORMCONTROL_KNOWLEDGE_WORKER_TOKEN` длиной не меньше 32 символов. Его же значение поместите в локальный `.env` как `KNOWLEDGE_WORKER_TOKEN`. `KNOWLEDGE_PORTAL_URL` указывает на HTTPS-адрес `/normcontol/api/v2`; для изолированного Compose-портала допустим `http://knowledge-portal:8110/normcontol/api/v2`. Новые документы не отправляются напрямую в Qdrant: обработчик фиксирует оригинал, структуру и кандидатов в общей канонической базе, а индексатор строит производное поколение.

```bash
docker compose -f deploy/knowledge-v2/compose.yaml --env-file deploy/knowledge-v2/.env --profile worker up -d --build
```

Профиль `worker` не включается до задания токена и подготовки API портала. Сервис умеет принимать DOCX, DOC и PDF; его образ содержит LibreOffice, Poppler, Tesseract ru/en и `pypdf`. Непрочитанные фрагменты остаются явно помеченными. Контейнер обработчика и индексатор делят один каталог `KNOWLEDGE_DATA_PATH`; база SQLite имеет одного владельца данных и не размещается на сетевом томе между VPS и локальным компьютером.

Для временного локального испытания профиля `portal` заполните `APP_SECRET`, `APP_HOSTS`, `APP_ORIGINS` и `KNOWLEDGE_WORKER_TOKEN`. Сначала примените миграции командой `docker compose --profile portal run --rm knowledge-portal python manage.py migrate --noinput`, затем запустите профиль. Он использует отдельный том `portal-v2` и слушает только `127.0.0.1:8110`.

## Обновление и данные

Обновляйте только после штатной паузы, холодной копии и проверки курсоров. `docker compose up -d --build` пересоздаёт сервисы с сохранением постоянных томов. **Не используйте `down -v`** для рабочей установки. Пошаговая согласованная копия SQLite, файлов, Qdrant и портала, а также восстановление только в пустую установку описаны в [INSTALL.md](INSTALL.md). Публикацию нового выпуска нельзя считать завершённой до подтверждения готовности FTS и Qdrant.

Установочная запись конкретного хоста и проверенные версии: [CONTINUE.md](../../deliverables/host-environment-20260924/CONTINUE.md). Протоколы загрузки, выделения обязанностей и поиска описаны в `docs/KNOWLEDGE-V2-INGEST.md`, `docs/KNOWLEDGE-V2-REQUIREMENTS.md`, `docs/KNOWLEDGE-V2-SEARCH.md`.

## Нормативный исполнитель

Этап 6 добавляет отдельный `knowledge_v2.review_worker` в этот же образ worker. Закрепление выпусков, контроль доказательств, пауза и отчёт описаны в [KNOWLEDGE-V2-REVIEW.md](../../docs/KNOWLEDGE-V2-REVIEW.md). Запуск выполняется явно для владельца проверки; действующий портал и задания nc5 не переключаются автоматически.

Для редактора нормативных связей, матрицы комплекта и отдельных `expert-worker`/`review-worker` используйте раздел 9.1.6–9.1.7 в [INSTALL.md](INSTALL.md).
