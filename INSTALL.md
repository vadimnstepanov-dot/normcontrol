# Установка NormControl 1.0.0

Выпуск содержит исходники портала, движка, Knowledge v2 и Docker-компонентов. Модели, Microsoft Word, нормативные документы, пользовательские данные и секреты устанавливаются отдельно. Контейнерные образы из примеров нужно собрать; публикация в реестре образов не предполагается.

## Выбор схемы

| Схема | Назначение | Инструкция |
| --- | --- | --- |
| Windows, автономный движок | Локальные проверки и разработка; модель и Word на рабочей станции | [Windows](INSTALL-WINDOWS.md) |
| Linux/VPS, портал | Несколько пользователей; внешний обработчик выполняет проверки | [Linux](INSTALL-LINUX.md) |
| Windows + WSL/Docker | Обработчик, подготовка, очередь и TLS-шлюз в Linux; модель, Word и мониторинг в Windows | [WSL/Docker](deploy/native-core/README.md) |
| Linux, автономный движок | DOCX и совместимая локальная LLM; без Word COM | [Linux](INSTALL-LINUX.md) |

Для совместной работы рекомендуется HTTPS-портал на VPS и отдельный компьютер с моделью. Порталу не нужна GPU. Knowledge v2 устанавливается дополнительно по [своей инструкции](deploy/knowledge-v2/INSTALL.md); опубликованные нормативные редакции нужно подготовить до проверки СТО.

## Получение версии

```sh
git clone --branch 1.0.0 https://github.com/vadimnstepanov-dot/normcontrol.git
cd normcontrol
```

Основные зависимости: Python 3.11/3.12, Git; для тестов рекомендуется Python 3.12 и Node.js 22. WSL/Docker-схема требует WSL 2 с Linux-дистрибутивом, Docker Engine и Compose. Версия пакета WSL и поколение виртуализации дистрибутива — разные параметры.

## Документы и память

DOCX читается непосредственно. В основном Docker-обработчике DOC читается Microsoft Word через закрытый Windows-мост, без промежуточного DOCX; результат с правками сохраняется как DOC. Старый автономный Windows CLI использует рабочую DOCX-копию. Linux без Windows-моста не предоставляет прямой DOC-конвейер.

Резерв допуска в очередь — 2048 МиБ, предел кэша документов — 1024 МиБ. Это отдельные настройки от лимита WSL и лимитов контейнеров. Общая память должна вмещать ОС, модель, KV-кэш, Knowledge v2 и основные контейнеры. При нехватке памяти задача ожидает допуска.

## Проверка чистой установки

В отдельном виртуальном окружении, не на производственной базе:

```sh
python -m pip install -r requirements-test.txt -c requirements-test.lock
python -m pip check
python tools/test_release.py
node --test normcontrol-web/tests/chat_controls.test.cjs
```

Сценарий запускает тесты движка, Knowledge v2, обработки документов, Docker-адаптеров и Django в свежем временном хранилище. Синтетические фикстуры включены; доступ к закрытым СТО не нужен. Живые интеграционные проверки модели выполняются отдельно.

После установки проверьте вход, загрузку учебного DOCX, роли целевого документа и основания, получение задания обработчиком, heartbeat и экспорты. DOC и Word проверьте отдельно на машине с Word. Для СТО подтвердите публикацию и фактический охват нормативной редакции: health-check этого не доказывает.

## Обновление существующей установки

1. Покажите страницу плановых работ с ожидаемым сроком: `planned_maintenance on`. Независимый маршрут прокси сохраняет страницу при остановке Django.
2. Сохраните контрольную точку, дождитесь завершения текущего запроса модели и остановите только заменяемые компоненты. Не отменяйте пользовательские паузы.
3. Сделайте согласованную резервную копию `APP_DATA`, базы и файлов обработчика, индексов, нормативных редакций, конфигураций и ключей вне Git. Для SQLite используйте backup API или остановленную базу; копирование одного активного файла без WAL недостаточно.
4. Получите тег `1.0.0`, установите зависимости или соберите образы, выполните миграции Django и сборку статики. Команды приведены в отдельных инструкциях.
5. Проверьте health, токены, TLS, идентификаторы сохранённых задач, документов и результатов. Не переводите старый план на новую реализацию подменой хэша: используйте совместимый обработчик или новый запуск с сохранением старого результата.
6. Возобновите только принадлежащие обновлению паузы и выключите страницу работ после проверки сервиса. При задержке обновите ожидаемый срок.

Не используйте `git reset --hard` для обновления установки с локальными изменениями. Не восстанавливайте старый снимок поверх новых результатов. Токены, закрытые нормативы, документы и подробные журналы проверки не добавляются в Git.
